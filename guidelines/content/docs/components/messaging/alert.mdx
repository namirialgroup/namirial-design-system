## Overview

An alert lives inline in the page layout — above a form, at the top of a section — and stays visible until the underlying condition changes or the user dismisses it. It never floats above content and never disappears on its own.

### When to use

Use an alert when:

- The information applies to the whole page or section, not a single field (system status, an expired session, a pending review).
- The message should persist until the user deals with it or navigates away — not vanish after a few seconds.

Consider another component when:

- The feedback is tied to a single field's value — use the input's own error/warning/success state instead.
- The message is a one-off confirmation of an action the user just took and can safely disappear on its own — use [Toast](/docs/components/messaging/toast).
- The message needs to interrupt the user and block further action until resolved — use a [Dialog](/docs/components/messaging/dialogs).

## Anatomy

An alert is a single-row container with a leading icon, a text body, and an optional close button — three parts sharing one set of intent tokens.

## Content types

### With a link

`.nm-alert__link` inherits the alert's text color and only adds weight and underline — it never introduces a separate link color, so it stays legible against every intent.

<div className="example">
  <div className="nm-alert nm-alert--warning" style={{width:'360px'}}>
    <span className="nm-alert__icon"><Ic n="alert-triangle" s={24} /></span>
    <span className="nm-alert__body">Your card expires soon. <span className="nm-alert__link">Update payment method</span>.</span>
  </div>
</div>

### Dismissible

Add `.nm-alert__close` as a real `<button>` when the condition is safe for the user to acknowledge and hide. Don't add a close button when the alert reflects a state the user still needs to resolve.

<div className="example">
  <div className="nm-alert nm-alert--info" style={{width:'360px'}}>
    <span className="nm-alert__icon"><Ic n="info" s={24} /></span>
    <span className="nm-alert__body">We've updated our terms of service.</span>
    <button type="button" className="nm-alert__close" aria-label="Dismiss"><Ic n="x" s={16} /></button>
  </div>
</div>

## Accessibility

#### Semantics

- Give the alert container `role="status"` for informational intents, or `role="alert"` for `negative`/`warning` so assistive tech announces it immediately.
- The icon is decorative and duplicates the intent already carried by color and text — mark it `aria-hidden="true"`.

#### Dismissal

- The close button must be a real `<button>` with `aria-label="Dismiss"` (or similarly explicit) — never a bare icon with a click handler.
- Removing an alert from the DOM on dismiss is enough; no focus management is required unless the alert was the page's only interactive landmark.

#### Color

- Never rely on the border/background color alone to communicate severity — the icon and text must independently make the intent clear.

## Implementation

No JavaScript is required for a static alert — it's a styled `<div>` with a text body, only the optional close button needs a click handler.

```html
<link rel="stylesheet" href="namirial-theme.css">

<div class="nm-alert nm-alert--warning" role="alert">
  <span class="nm-alert__icon" aria-hidden="true"><!-- icon --></span>
  <span class="nm-alert__body">Your trial ends in 3 days.</span>
  <button type="button" class="nm-alert__close" aria-label="Dismiss"><!-- x icon --></button>
</div>
```

#### CSS classes

| Class | Values | Default |
|-------|--------|---------|
| `nm-alert--{intent}` | primary · secondary · accent · info · positive · negative · warning — omit for `info` | — (`info`) |
| `nm-alert__icon` | Leading icon slot, 24×24px | — |
| `nm-alert__link` | Inline emphasized link inside the body | — |
| `nm-alert__close` | Dismiss button, 24×24px, must be a `<button>` | — |
