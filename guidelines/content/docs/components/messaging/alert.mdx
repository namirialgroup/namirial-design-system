## Overview

An alert will float at the bottom of the viewport above the content or live inline within the page layout near the interaction area — for example, at the top of a section, above a form, in a dialog, or within a specific page content. It stays visible until the underlying condition changes or the user dismisses it.

### When to use

Use an alert when:
- The information needs attention and deserves a prominent placement (e.g. system status, an expired session, a pending review).
- The action needs prominent feedback because no other visual change indicates the result (e.g. saving changes without navigating away).

Consider another component when:
- The feedback is tied to a single field's value — use the input's own error/warning/success state instead.
- The information is minor or only relevant to a nearby interaction - use [Message](/docs/components/messaging/message).
- The feedback requires user action or decision but should not block the UI — use [Toast](/docs/components/messaging/toast) (e.g. cookie consent or an action-required system notification).
- The message needs to interrupt the user and block further action until resolved — use a [Dialog](/docs/components/messaging/dialogs).

## Content types

### With a link

`.nm-alert__link` inherits the alert's text color and only adds weight and underline — it never introduces a separate link color, so it stays legible against every intent.

<div className="example">
  <div className="nm-alert nm-alert--warning" style={{width:'500px'}}>
    <span className="nm-alert__icon"><Ic n="alert-triangle" s={24} /></span>
    <span className="nm-alert__body">Your card expires soon. <span className="nm-alert__link">Update payment method</span>.</span>
  </div>
</div>

### Dismissible

Add `.nm-alert__close` as a real `<button>` when the condition is safe for the user to acknowledge and hide. Don't add a close button when the alert reflects a state the user still needs to resolve.

<div className="example">
  <div className="nm-alert nm-alert--info" style={{width:'500px'}}>
    <span className="nm-alert__icon"><Ic n="info" s={24} /></span>
    <span className="nm-alert__body">This document is shared. Changes affect all users.</span>
    <button type="button" className="nm-alert__close" aria-label="Dismiss"><Ic n="x" s={16} /></button>
  </div>
</div>

## Position & full-width

`.nm-alert` carries no `width`, no `position`, and no placement logic of its own — it's a `display:flex` row with intrinsic sizing. Where it sits on the page and how wide it renders are entirely decided by the markup around it, not by a modifier class.

### Position possibilities

An alert isn't anchored to a trigger, so it just sits wherever it's placed in the document flow:

- **Page banner** — floating above the main content.
- **Section / inline banner** — scoped to a section, card, or form.
- **Dialog context** — inside `.nm-dialog__body`, inheriting the dialog's width.

### Full-width behaviour

`.nm-alert` sets no `width`, so it always stretches to fill 100% of its parent. Don't give it a fixed width; let it track its container at every breakpoint.

On very large screens, cap the alert with a max-width and center it. Beyond a certain viewport width, a full-bleed alert’s line length becomes hard to read.

<div className="example">
  <div style={{maxWidth:'960px', width:'100%'}}>
    <div className="nm-alert nm-alert--info" style={{width:'100%'}}>
      <span className="nm-alert__icon"><Ic n="info" s={24} /></span>
      <span className="nm-alert__body">Still full-width at every size, capped at max-width: 960px only once the viewport is wide enough to need it.</span>
    </div>
  </div>
</div>

## Accessibility

#### Semantics

- Give the alert container `role="status"` for informational intents, or `role="alert"` for `negative`/`warning` so assistive tech announces it immediately.
- The icon is decorative and duplicates the intent already carried by color and text — mark it `aria-hidden="true"`.

#### Dismissal

- The close button must be a real `<button>` with `aria-label="Dismiss"` (or similarly explicit) — never a bare icon with a click handler.
- Removing an alert from the DOM on dismiss is enough; no focus management is required unless the alert was the page's only interactive landmark.

#### Color

- Never rely on the border/background color alone to communicate severity — the icon and text must independently make the intent clear.

## Implementation

No JavaScript is required for a static alert — it's a styled `<div>` with a text body, only the optional close button needs a click handler.

```html
<link rel="stylesheet" href="namirial-theme.css">

<div class="nm-alert nm-alert--warning" role="alert">
  <span class="nm-alert__icon" aria-hidden="true"><!-- icon --></span>
  <span class="nm-alert__body">Your trial ends in 3 days.</span>
  <button type="button" class="nm-alert__close" aria-label="Dismiss"><!-- x icon --></button>
</div>
```

#### CSS classes

| Class | Values | Default |
|-------|--------|---------|
| `nm-alert--{intent}` | primary · secondary · accent · info · positive · negative · warning — omit for `info` | — (`info`) |
| `nm-alert__icon` | Leading icon slot, 24×24px | — |
| `nm-alert__link` | Inline emphasized link inside the body | — |
| `nm-alert__close` | Dismiss button, 24×24px, must be a `<button>` | — |
