## Overview

Both patterns share the same `.nm-dialog` card and sit inside a `.nm-dialog-backdrop` that dims and blocks the page behind them. They differ in scope: a Confirmation Dialog only ever asks for a single yes/no decision; a Modal Dialog can hold any short, focused task.

### When to use

Use confirmation dialog when:

- Before a destructive or hard-to-reverse action (delete, discard, cancel a subscription).
- The decision is binary — proceed or don't — and needs no other input, but always relaying on a critical action or warning.

Use modal dialog when:

- A short, self-contained task that needs the user's full attention (e.g. a quick edit form, a single setting).

Consider another component when:

- The feedback doesn't need to block the page — use [Alert](/docs/components/messaging/alert) or [Toast](/docs/components/messaging/toast).
- The content is anchored to a specific trigger and the rest of the page should stay usable — use [Popover](/docs/components/messaging/popover).

## Intent variants

Confirmation dialog pattern share the same seven intent classes, but in practice only a few get used: Modal Dialog stays neutral (no intent class — a plain `.nm-dialog`), and Confirmation Dialog only reaches for `warning` or `negative` to match the caveat or destructive action it's confirming. The card fill always stays neutral (`--nm-dialog-bg`) regardless of intent.

## Accessibility

#### Semantics

- Give the card `role="dialog"` (or `role="alertdialog"` for a Confirmation Dialog on a destructive action), `aria-modal="true"`, and label it with `aria-labelledby` pointing at `.nm-dialog__title`.
- Describe it with `aria-describedby` pointing at `.nm-dialog__description`.

#### Focus

- On open, move focus to the dialog — the title, the first focusable element, or the least destructive footer action (never the destructive one by default).
- Trap Tab/Shift+Tab focus inside the dialog while it's open; nothing behind the backdrop should be reachable.
- On close, return focus to whatever triggered the dialog.

#### Keyboard

- `Escape` closes the dialog, equivalent to the close button — unless the dialog represents an unsavable, irreversible in-progress action.

#### Labeling

- Never make the destructive action the visually dominant one by default focus/color alone — pair it with a clear, specific label.

## Implementation

Open/close state, focus trapping, and backdrop click handling need JavaScript (or the native `<dialog>` element); the card and backdrop themselves are pure CSS.

```html
<link rel="stylesheet" href="namirial-theme.css">

<div class="nm-dialog-backdrop">
  <div class="nm-dialog nm-dialog--confirmation nm-dialog--negative" role="alertdialog" aria-modal="true" aria-labelledby="dlg-title" aria-describedby="dlg-desc">
    <div class="nm-dialog__header">
      <span class="nm-dialog__header-icon" aria-hidden="true"><!-- icon --></span>
      <h3 class="nm-dialog__title" id="dlg-title">Delete this document?</h3>
    </div>
    <div class="nm-dialog__body">
      <p class="nm-dialog__description" id="dlg-desc">This action can't be undone.</p>
    </div>
    <div class="nm-dialog__footer">
      <button type="button" class="nm-button nm-button--secondary nm-button--md">Cancel</button>
      <button type="button" class="nm-button nm-button--negative nm-button--md">Delete</button>
    </div>
  </div>
</div>
```

#### CSS classes

| Class | Values | Default |
|-------|--------|---------|
| `nm-dialog--{size}` | xs · sm · md · lg · xl — omit for the `md` default (Modal Dialog only) | — (`md`) |
| `nm-dialog--confirmation` | Fixed-width Confirmation Dialog layout, indented body | — |
| `nm-dialog--collapsible` + `.is-collapsed` | Animates body/footer open/closed | — |
| `nm-dialog--{intent}` | primary · secondary · accent · info · positive · negative · warning | — |
| `nm-dialog__close` / `nm-dialog__toggle` | Close button / collapse toggle, 24×24px | — |
| `nm-dialog-backdrop` | Full-screen dimmed backdrop wrapping the card | — |
