## Overview

Toasts provide floating, non-blocking notifications for updates, system messages, and feedback that requires user attention. They appear independently of the page layout and can remain visible until dismissed or the required action is completed.

### When to use

Use a toast when:
- You need to communicate an update or system message without interrupting the user's current task.
- The information requires the user's attention or a decision, but should not block the UI.
- You need to provide contextual feedback or actions that remain accessible while the user continues working.

Consider another component when:
- The feedback is brief and tied to a specific interaction or content area — use [Message](/docs/components/messaging/message).
- The information needs prominent placement within the current context — use [Alert](/docs/components/messaging/alert).
- The user must resolve an issue before continuing — use [Dialog](/docs/components/messaging/dialogs).

## Accessibility

#### Semantics

- Render the toast region with `role="status"` (`aria-live="polite"`) for routine confirmations, or `role="alert"` (`aria-live="assertive"`) for failures that need immediate attention.
- Mark the icon `aria-hidden="true"`.

#### Focus

- A toast must never steal keyboard focus on appearance — it's a passive notification, not an interruption.
- Any action button inside it must still be reachable by keyboard for users who choose to engage with it.

  <div class="nm-toast__notification">

    <div class="nm-toast__text">
      <span class="nm-toast__title">Invoice sent</span>
      <span class="nm-toast__body">Delivered to client.</span>
    </div>
    <button type="button" class="nm-toast__close" aria-label="Dismiss"><!-- x icon --></button>
  </div>
