## Overview

A switch and a checkbox both represent a binary on/off state, but they carry different promises to the user: flipping a switch takes effect the instant it's flipped, while a checkbox is understood to be staged until the surrounding form is submitted.

### When to use

- A setting that applies instantly, with no "Save" button in sight (`Dark mode`, `Auto-renew subscription`, `Two-factor authentication`)
- A single, standalone preference in a settings page, viewed on its own rather than inside a longer form

### When not to use

- Inside a form with an explicit submit action — use a **checkbox** so the "staged, not yet applied" semantics are honest.
- A choice among 3+ mutually exclusive named options — use **radio** or a **segmented control**.

## Anatomy

A switch is a compound component: an outer track (`.nm-switch`), a visually-hidden native `<input type="checkbox">` (`.nm-switch__input`) that carries all real interaction and focus, and a visible thumb (`.nm-switch__thumb`) that slides between the two ends of the track. The thumb's own `::after` renders a small checkmark (or dash, when indeterminate) once it reaches the "on" position.

## Selection states

Like checkbox, a switch supports a **middle** (indeterminate) state for summarizing a group of settings that aren't all in the same position. Unlike checkbox, this is a class on the outer track (`.is-indeterminate`) rather than a native DOM property, since the visible thumb position (centered) isn't something the native `indeterminate` property drives on its own here.

## Interaction states

Hover targets the whole track, not just the thumb — this matches the larger click/tap target real switches have.

<div className="example">
  <span className="nm-switch"><input type="checkbox" className="nm-switch__input" defaultChecked /><span className="nm-switch__thumb"></span></span>
  <span className="nm-switch" data-state="hover"><input type="checkbox" className="nm-switch__input" defaultChecked /><span className="nm-switch__thumb"></span></span>
  <span className="nm-switch is-readonly"><input type="checkbox" className="nm-switch__input" defaultChecked tabIndex={-1} aria-readonly="true" /><span className="nm-switch__thumb"></span></span>
  <span className="nm-switch" data-state="focus"><input type="checkbox" className="nm-switch__input" defaultChecked /><span className="nm-switch__thumb"></span></span>
</div>

<p className="caption">On · default → hover → read-only → focus</p>

#### No disabled state

Switches never ship the native "greyed out" disabled look. If a setting is off the table for now, use **read-only** so its current position stays legible and its value still submits with the form.

#### Read-only implementation

Put `.is-readonly` on the outer `.nm-switch` track (that's what the CSS targets) and `tabindex="-1"` / `aria-readonly="true"` on the inner `.nm-switch__input`, since that's the real focusable element:

```html
<span class="nm-switch is-readonly">
  <input type="checkbox" class="nm-switch__input" checked tabindex="-1" aria-readonly="true">
  <span class="nm-switch__thumb"></span>
</span>
```

## Accessibility

#### Semantics

- The underlying element is `<input type="checkbox">`. Add `role="switch"` on the input so assistive tech announces it as a switch rather than a generic checkbox, and mirror its state with `aria-checked`.
- Wrap it in `.nm-choice-field`'s `<label>` so the visible text is the accessible name.

#### Middle state

- Set `.is-indeterminate` on the outer `.nm-switch` (not a native property here). Also set `aria-checked="mixed"` on the inner input so screen readers announce it correctly.

#### Read-only

- Put `.is-readonly` on the outer `.nm-switch` and `tabindex="-1"` / `aria-readonly="true"` on the inner `.nm-switch__input` — the real focusable element. This removes it from the tab order while keeping its value in the form.

#### Keyboard

- Tab moves focus to the hidden `<input>`; Space toggles it.
- Focus uses `:focus-visible` on the input, but the ring should visually wrap the track — verify it renders around the full `.nm-switch`, not just the invisible input, when you implement it.

## Implementation

The visible track and thumb are decorative; the real interactive element is the hidden checkbox input. No JavaScript is required for basic on/off — only for the middle state, which has no native equivalent.

```html
<link rel="stylesheet" href="namirial-theme.css">

<label class="nm-choice-field">
  <span class="nm-switch">
    <input type="checkbox" class="nm-switch__input" role="switch">
    <span class="nm-switch__thumb"></span>
  </span>
  <span class="nm-choice-field__label">Dark mode</span>
</label>
```

#### CSS classes

| Class | Applies to | Values |
|-------|-----------|--------|
| `nm-switch` | Outer track | Fixed 48×24px — no size modifiers |
| `nm-switch__input` | Inner `<input type="checkbox">` | Visually hidden, carries real focus/interaction |
| `nm-switch__thumb` | Sliding knob | Sibling of `nm-switch__input`, positioned via `:checked` |
| `is-indeterminate` | Outer track | Middle state — set manually, no native equivalent |
| `is-readonly` | Outer track | Pair with `tabindex="-1"` / `aria-readonly="true"` on the input |
