## Overview

An input is the default control for collecting a single line of free-form text or data, such as a name, email address, amount, or date. Always pair it with a clear label. When a specific format is expected, provide helpful guidance before users enter their information.

### When to use

Use an input when:

- You need to collect a single line of free-form data and the range of valid responses is too broad to present as a predefined list.
- The input is part of a composite field, paired with a unit, symbol, or another control (for example, a currency selector or measurement unit).

Consider another component when:

- Users need to choose from a fixed set of options (use Select, Radio buttons, or Checkboxes).
- Users need to enter longer or multi-line content (use Textarea).
- The value requires a specialised input pattern or interaction (e.g. Code, Search).

**Required fields** <br/>
Do not indicate required fields with an asterisk (*). Use the label “(required)” instead.

If all or most fields in a form are mandatory, indicate this at the beginning of the form by using one of the following statements:

- “All fields are required.”
- “All fields are required unless otherwise indicated.”

In forms where only some fields are optional, mark those fields with “(optional)”.

## Sizes

Input ships in five sizes — `xs`, `sm`, `md`, `lg`, `xl` — with `sm` as the default. `sm` isn't a modifier class you add; it's what `.nm-input` renders with no size class at all. Apply `xs`, `md`, `lg`, or `xl` explicitly to size away from the default.

#### Choosing a size

- `xs` — dense tables, inline editing, filter bars
- `sm` — default for forms and dialogs (just `.nm-input`, no size class)
- `md` — standard content forms, cards
- `lg` — prominent single-field forms, onboarding
- `xl` — signing surfaces, marketing lead-capture

Use `.nm-input__icon-leading` for an icon that identifies the field's format (an envelope for email). Use `.nm-input__icon-trailing` for a secondary content icon, like a chevron for select, or for a validation icon (see [Interaction & validation states](#states)). Both slots share the same `--nm-input-icon` color as the field's border and help text, so any icon placed in either one recolors together with `nm-input--error` / `nm-input--warning` / `nm-input--success` — there's no separate always-neutral icon slot in the current stylesheet.

### Clear

A trailing icon becomes an actual clear action once the field has a value — render it as a `<button>`, not a decorative icon.

`.nm-input__icon-leading` and `.nm-input__icon-trailing` both pick up `--nm-input-icon`, which is redefined by `nm-input--error` / `nm-input--warning` / `nm-input--success` — so any icon in either slot recolors with the field. There's no separate slot that stays neutral once an intent is set, so when a field has both a format icon (like `calendar`) and validation feedback, drop the format icon and show only the validation icon — showing both would recolor the format icon too and read as if the format itself were invalid.

### Input group

#### No disabled state

Like every Namirial control, inputs never ship a browser-default disabled look. Use **read-only** (`nm-input--readonly`) when a value can't change right now but should still be visible and still submit with the form.

#### Focus

Focus is rendered as a 2px `box-shadow` ring in `--nm-input-focus-ring`, not an outline — it sits flush against the container instead of floating outside it. It triggers on `:focus-within`, so clicking anywhere in the container (including a leading icon) focuses the field.

## Accessibility

#### Semantics

- Always associate the label with the field — wrap both in `.nm-input` and use `for`/`id`, or nest the `<input>` inside the `<label>`.
- Use the correct `type` (`email`, `tel`, `number`, `date`) so mobile keyboards and browser validation match the data.

#### Help & error text

- Connect help and error text to the field with `aria-describedby` so screen readers announce it alongside the label.
- On error, add `aria-invalid="true"` to the `<input>` in addition to the `nm-input--error` class — the class is visual only.

#### Keyboard

- Tab moves focus into the field; all native text-editing shortcuts work unmodified.
- Focus uses `:focus-within` on the container, so clicking a leading/trailing icon also focuses the field.

#### Labeling

- Icon-only trailing actions (like Clear) must be a real `<button>` with an `aria-label`, never a bare icon with a click handler.
- Never rely on the border color alone to communicate validation state — pair it with visible help text.

## Implementation

No JavaScript is required for a plain input — it's native HTML styled by CSS classes.

```html
<link rel="stylesheet" href="namirial-theme.css">

<div class="nm-input nm-input--md">
  <label class="nm-input__label">
    Email address
    <span class="nm-input__required">(required)</span>
  </label>
  <div class="nm-input__container">
    <input class="nm-input__field" placeholder="you@company.com">
  </div>
  <span class="nm-input__help">We'll never share your email.</span>
</div>
```
