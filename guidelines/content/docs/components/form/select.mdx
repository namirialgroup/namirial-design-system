## Overview

The Select component lets users choose one or more values from a predefined list of options. It provides a controlled way to capture structured input by limiting selections to values that have already been defined.

### When to use

Use the Select component when:

- Users need to choose from a fixed set of mutually exclusive options, such as a country, language, document type, or currency.
- The number of options is too large for radio buttons but still manageable as a list (typically around 5–50 options).
- Users need to select multiple items from a predefined set, such as tags, roles, or categories (using a multi-select variant).

## Accessibility

Namirial select follows the ARIA combobox pattern — it is not a native `<select>`, so all keyboard and screen-reader behavior must be wired explicitly.

#### Semantics

- Trigger: `role="combobox"`, `aria-expanded`, `aria-controls` pointing at the menu's `id`, `aria-haspopup="listbox"`.
- Menu: `role="listbox"` (or `role="listbox" aria-multiselectable="true"` for multi-select), each option `role="option"` with `aria-selected`.
- Keep a hidden native `<select>` or a hidden `<input>` in sync with the chosen value so the field still submits inside a plain HTML `<form>`.

#### Keyboard

- Enter or Space on the trigger opens the menu; Escape closes it and returns focus to the trigger.
- Arrow Up / Down moves through options without closing the menu; Enter commits the highlighted option.
- Type-ahead: typing a letter jumps to the next option starting with it.

#### Labeling

- The trigger needs the same label association as input — `for`/`id` or nesting.
- Disabled options use `aria-disabled="true"` and `nm-dropdown__item--disabled`; they stay in the DOM and are announced, just not selectable.
