## Overview

Select trades the openness of an input for the safety of a fixed list — the user can only submit a value you've already validated. Reach for it whenever the answer space is small enough to enumerate and stable enough not to need free text.

### When to use

- A closed set of mutually-exclusive options — country, document type, currency
- A list too long for radio buttons but too structured for free text (roughly 5–50 items)
- Multi-select from a known set of tags, roles, or categories

### When not to use

- Two to four always-visible options — a **radio group** or **segmented control** reads faster with no extra click.
- A value the user needs to type or that isn't in any fixed list — use **input**.
- A large, unstructured, or searchable catalog (documents, contacts, products) — use **search**.

## Multi-select

When more than one value can be chosen, render each selection as an `.nm-tag` inside the trigger instead of plain text, and mark matching menu items with `.nm-dropdown__item--multi` (a checkbox-style marker instead of the single-select dot).

## Accessibility

Namirial select follows the ARIA combobox pattern — it is not a native `<select>`, so all keyboard and screen-reader behavior must be wired explicitly.

#### Semantics

- Trigger: `role="combobox"`, `aria-expanded`, `aria-controls` pointing at the menu's `id`, `aria-haspopup="listbox"`.
- Menu: `role="listbox"` (or `role="listbox" aria-multiselectable="true"` for multi-select), each option `role="option"` with `aria-selected`.
- Keep a hidden native `<select>` or a hidden `<input>` in sync with the chosen value so the field still submits inside a plain HTML `<form>`.

#### Keyboard

- Enter or Space on the trigger opens the menu; Escape closes it and returns focus to the trigger.
- Arrow Up / Down moves through options without closing the menu; Enter commits the highlighted option.
- Type-ahead: typing a letter jumps to the next option starting with it.

#### Labeling

- The trigger needs the same label association as input — `for`/`id` or nesting.
- Disabled options use `aria-disabled="true"` and `nm-dropdown__item--disabled`; they stay in the DOM and are announced, just not selectable.

## Implementation

Select needs a small amount of JavaScript to toggle the menu and sync the chosen value — there is no native element to lean on.

```html
<link rel="stylesheet" href="namirial-theme.css">

<div class="nm-input nm-input--select nm-input--md">
  <label class="nm-input__label" id="country-label">Country</label>
  <div class="nm-input__container" role="combobox"
       aria-haspopup="listbox" aria-expanded="false"
       aria-controls="country-listbox" aria-labelledby="country-label" tabindex="0">
    <span class="nm-input__select-value--placeholder">Select a country</span>
    <span class="nm-input__icon-trailing"><!-- chevron icon --></span>
  </div>
  <ul class="nm-dropdown" role="listbox" id="country-listbox" hidden>
    <li class="nm-dropdown__item" role="option">Italy</li>
    <li class="nm-dropdown__item" role="option">Germany</li>
  </ul>
</div>
```

| Class | Values | Default |

| `nm-dropdown__item--multi` | Checkbox-style marker for multi-select | — |
| `nm-dropdown__item--disabled` | Non-selectable option | — |
