## Overview

The Textarea component is designed for entering free-form text that spans multiple lines. It provides enough space for users to write descriptions, comments, notes, or other longer content while supporting the same labeling, help text, and validation patterns as a standard input.

### When to use
Use the Textarea component when:
- Users need to enter messages, comments, or notes of varying length.
- The expected input consists of one or more sentences, such as descriptions or explanations, rather than a single value like a name or email address. For single-line values, use an Input.
- Users need to add free-form information to a record, for example internal comments, signing instructions, or additional context.
- The content doesn't need document-level formatting such as headings, images, or tables — for that, use a Rich Text Editor. If it only needs light emphasis (bold, italic, underline, lists, links), add the optional [formatting toolbar](#toolbar) instead of reaching for a full editor.
- The input is intended for longer text, not short fixed-length values such as verification codes or PINs. For verification codes or PINs, use a Code Field.

#### Tokens and values that drive each part

| Part | Role | Source |
|------|------|--------|
| Label / help / container fill / border | Same as input | `--nm-input-*` (see [Input](/docs/components/form/input)) |
| Container alignment | Top-aligned instead of centered | `.nm-input--textarea .nm-input__container { align-items: flex-start }` |
| Field line height | Roomier for multi-line reading | `.nm-input--textarea .nm-input__field { line-height: 1.5 }` |
| Field resize | User-resizable height only | `.nm-input--textarea .nm-input__field { resize: vertical }` |

#### Choosing a row count

Set `rows` to the number of lines you expect the average answer to take — 2–3 for a short note, 5–6 for an open-ended description. Let the user grow it further with the resize handle rather than guessing high and leaving empty space.

#### Resize behavior

`resize: vertical` lets the user drag the bottom-right corner to grow the field, without letting it stretch wider than its container and break the surrounding layout. Never set `resize: none` unless the field's height is already generous enough for the longest realistic answer.

#### Toolbar

Textarea can surface a lightweight formatting toolbar above the field for content that benefits from basic emphasis, without the overhead of a full Rich Text Editor. Nest a `.nm-input__toolbar` row before the `<textarea>` and add `nm-input__container--toolbar` to the container — it stacks the toolbar above the field and clips both to the container's rounded corners.

- The `Normal` control opens a block-style menu (paragraph, heading levels, quote); keep it a `<button aria-haspopup="listbox">` wired to your dropdown/menu component, not a native `<select>`, so its width can hug the label.
- Keyboard users still need the standard shortcuts (`Cmd/Ctrl+B`, `+I`, `+U`) — the toolbar buttons should mirror those, not replace them.

## Accessibility

#### Semantics

- Associate the label the same way as input — `for`/`id` or nesting inside `.nm-input__label`.
- If you enforce a character limit, expose the remaining count in a live region, not just visually.

#### Keyboard

- Tab moves focus in and out; the resize handle is native and keyboard-inaccessible by design — don't make resizing the only way to see full content, ensure `overflow: auto` handles scrolling too.
- Enter inserts a newline (unlike input, where Enter often submits a form) — never intercept Enter to submit a form containing a textarea unless the user expects that.

#### Labeling

- Use `aria-describedby` to connect help text and any character-count indicator to the field.
- On error, set `aria-invalid="true"` alongside the `nm-input--error` class.
