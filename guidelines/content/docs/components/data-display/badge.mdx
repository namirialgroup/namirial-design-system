## Overview

A badge draws the eye to a number or a state without demanding a click. It carries very little content — a count, a short label, or nothing at all (the dot variant) — and almost always overlays or sits directly beside the element it describes.

### When to use

- To show an unread or pending count (`12` unread messages)
- To flag a short, glanceable status (`NEW`, `BETA`, `LIVE`)
- To indicate presence or activity without a count — the dot variant (`online`, `unread`, `has update`)

### When not to use

- For removable, text-first labels — use a **tag**.
- For a longer status message that needs explanation — use an **alert** or **tooltip**.
- As a standalone clickable element — a badge never carries its own interaction; wrap the element it's attached to instead.

## Anatomy

A badge is a small pill or circle: a saturated fill, a contrasting outline, and centered content. The dot variant strips the content and padding down to a single 8px circle.

  <div className="dot" style={{top:'70px',left:'150px'}}></div>

#### Tokens and values that drive each part

| Part | Role | Source |
|------|------|--------|
| Fill | Background | `--nm-badge-bg` |
| Outline | Border | `--nm-badge-border` (fixed to a surface-contrast color, not per-intent) |
| Content | Label / count color | `--nm-badge-fg` |
| Container | Shape | `border-radius: 999px`, min `20×20px` (`8×8px` for `--dot`) |

## Accessibility

- A badge is decorative-adjacent: it reinforces information that should also exist elsewhere (e.g. a count in an `aria-label` on the parent button, like `aria-label="Inbox, 12 unread"`).
- Never rely on the dot variant's color alone to convey status — pair it with a text label nearby or in an `aria-label`, since color alone isn't accessible to all users.
- All seven intents meet WCAG 2.2 **AA** contrast for content-over-fill.

## Token reference

| Token | Role |
|-------|------|
| `--nm-badge-bg` | Container fill |
| `--nm-badge-border` | Container outline (fixed, not per-intent) |
| `--nm-badge-fg` | Content color |

<p className="caption">Each <code>nm-badge--{'{intent}'}</code> modifier reassigns <code>--nm-badge-bg</code> and <code>--nm-badge-fg</code>. <code>{'{intent}'}</code> = primary · secondary · accent · info · positive · negative · warning.</p>

#### Index palette — categorical colors beyond the 7 intents

The same 10-hue categorical palette documented on the [Tag](/docs/components/data-display/tag#tokens) page is available for badges: `--palette-index-{'{n}'}-50` (soft), `-75` (mid), and `-100` (solid), for `{'{n}'}` = 1–10 — fixed hex values that don't remap per theme. There's no dedicated `nm-badge--index-{'{n}'}` modifier class, so wire them up per instance:
