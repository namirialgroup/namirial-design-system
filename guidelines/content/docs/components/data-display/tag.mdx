## Overview

A tag names a single attribute of the thing it's attached to — a category, a keyword, a status. Unlike a badge, a tag carries text as its primary content and can be dismissed by the user; unlike a button, it never triggers a page-level action on its own (only its optional remove control does).

### When to use

- To label content with a category or keyword (`React`, `Design System`)
- To show active filters that the user can remove (`Status: Active ✕`)
- To let users build a multi-value input, like recipients or skills

### When not to use

- To show a count or a short status indicator with no removable text — use a **badge**.
- To trigger navigation or a standalone action — use a **button** or **link**.
- For a single mutually-exclusive choice — use a **segmented control** or **radio group**.

## Anatomy

A tag is an inline flex container: a soft-tinted background, a tinted border, a text label, and an optional remove button. Every part reads its color from a `--nm-tag-*` custom property that the intent modifier reassigns.

## Accessibility

#### Semantics

- A plain tag is a `<span>` — it carries no interaction and needs no special role.
- The remove control must be a real `<button>` with an `aria-label` (`"Remove {'{'}value{'}'}"`); the icon alone is not accessible text.

#### Keyboard

- Non-removable tags are not focusable — they're static labels.
- The remove button follows normal tab order and activates on Space / Enter.

#### Contrast

- All seven intents meet WCAG 2.2 **AA** for label-over-background in both themes.

## Token reference

| Token | Role |
|-------|------|
| `--nm-tag-bg` | Container fill |
| `--nm-tag-border` | Container border |
| `--nm-tag-fg` | Label color |
| `--nm-tag-remove-fg` | Remove icon color at rest |
| `--nm-tag-remove-hover-fg` | Remove icon color on hover |

<p className="caption">Each <code>nm-tag--{'{intent}'}</code> modifier reassigns <code>--nm-tag-bg</code>, <code>--nm-tag-border</code>, and (for accent/info/positive/negative/warning) <code>--nm-tag-fg</code>. <code>{'{intent}'}</code> = primary · secondary · accent · info · positive · negative · warning.</p>

#### Index palette — categorical colors beyond the 7 intents

For content that needs many distinguishable colors with no semantic meaning (user-created labels, calendar categories, chart legends), `namirial-theme.css` ships a 10-hue categorical palette: `--palette-index-{'{n}'}-50` (soft), `--palette-index-{'{n}'}-75` (border/mid), and `--palette-index-{'{n}'}-100` (solid), for `{'{n}'}` = 1–10. These are fixed hex values — they don't remap per theme. There's no dedicated `nm-tag--index-{'{n}'}` modifier class yet, so wire them up per instance:

| Class | Values | Default |
