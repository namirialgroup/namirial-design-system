## Overview

A segmented control answers one question: *which of these mutually exclusive options is active right now?* Every option sits in a shared track; selecting one slides a filled indicator beneath it and flips its label to the active colour. There is always exactly one selection — the control has no empty state.

It looks like a button group, but the two solve different problems:

- A **segmented control** is a *single-select switch* — a styled track with a sliding indicator. The selection is the point.
- A **button group** is a *cluster of connected buttons* — it can be single-select, but it's just as happy holding independent commands (paginate, zoom, undo). No track, no sliding indicator.

### When to use

- To switch a view or layout (`List` / `Board` / `Calendar`)
- To pick one mode or scope (`All` / `Mine` / `Shared`, `Monthly` / `Yearly`)
- To filter a list by one mutually exclusive facet (`Active` / `Archived`)

### When not to use

- For independent commands or steppers — use a **button group**.
- For more than ~5 options, or long labels that won't fit on one line — use a **select** or **tabs**.
- To navigate between pages or sub-sections of content — use **tabs** or a **secondary nav**.
- For multi-select (more than one option on at once) — use **checkboxes** or **toggle chips**.

## Anatomy

A segmented control is a positioned flex track holding an absolutely-positioned indicator and a row of transparent buttons. The buttons sit above the indicator (`z-index:1`); the indicator slides under the active one with a 0.2s ease-out transition on `top` / `left` / `width` / `height`.

## Selection & the indicator

The selected item carries `aria-pressed="true"` (or `.is-selected`), which flips its label to `--nm-segmented-item-active-fg`. The visible "pill" behind it is the separate `.nm-segmented__indicator` element — and **its position is set in JavaScript**, not CSS. On selection (and on mount/resize), measure the active button and write the indicator's `top` / `left` / `width` / `height`; the 0.2s transition animates the slide for you.

<div className="example">
  <Seg ariaLabel="Sort order" size="md" start={1} options={[{label:'Newest'},{label:'Popular'},{label:'Oldest'}]} />
</div>

<p className="caption">Click between options to watch the indicator slide. Exactly one item is selected at all times.</p>

- Keep one option selected at all times — a segmented control never sits empty.
- Reposition the indicator on selection **and** on resize, font load, or container width change, or it will drift out of alignment.
- Order options by how the user reasons about them (chronological, small→large), not alphabetically.
- Two to five options. Beyond that, labels crowd and the slide stops feeling crisp.

## Sizes

## States

The track and items respond to interaction without ever changing the selection model.

<div className="example">
  <Seg ariaLabel="States demo" size="md" start={1} options={[{label:'Default'},{label:'Selected'},{label:'Hover me'}]} />
</div>

<p className="caption">md · the middle segment is selected; hover and focus any other to see the resting states.</p>

#### Selected vs. hover

- **Selected** is persistent: the indicator sits under the active item and its label uses the active colour. It survives focus moving away.
- **Hover** on an unselected item is a soft affordance only — it does not move the indicator. The indicator moves on **click**, then animates into place.

#### Focus

Each item is a real `<button>`, so it shows the standard `:focus-visible` ring. Because items sit above the indicator (`z-index:1`), the ring is never clipped. Never suppress it.

#### No disabled state

Like buttons, segmented controls don't ship a disabled appearance. If an option isn't currently valid, keep the control live and surface the reason inline rather than greying out a segment — a dead segment leaves users guessing.

## Accessibility

A segmented control is a single-select widget. Get the role and the selected-state attribute right and the rest follows from the native buttons.

#### Choosing a role

- **Toggle-button pattern** (used here): `role="group"` with an `aria-label` on the track, and `aria-pressed="true|false"` on each `<button>`. Simple and robust.
- **Radio pattern** (stricter): `role="radiogroup"` on the track, `role="radio"` + `aria-checked` on each item, with arrow-key roving focus so the control is a single Tab stop. Prefer this when the segmented control behaves exactly like a radio group.

Pick one and apply it consistently — don't mix `aria-pressed` with `role="radio"`.

#### Keyboard

- In the toggle pattern, Tab moves between segments and Space / Enter selects the focused one.
- In the radio pattern, Tab enters the group once; arrow keys move and select within it, per the WAI-ARIA radio pattern.

#### Labeling

- Give the track an `aria-label` (or `aria-labelledby`) naming what it controls (`"View"`, `"Billing period"`).
- Icon-only segments each need their own `aria-label` describing the option, not the glyph.
- Reflect the choice with `aria-pressed` / `aria-checked` — never rely on the indicator's colour alone. The indicator is `aria-hidden`.

#### Contrast & motion

- Selected and unselected labels meet WCAG 2.2 **AA** against their backgrounds in both themes.
- The 0.2s indicator slide is a short, non-essential transition; respect `prefers-reduced-motion` by disabling it for users who ask.

## Implementation

Wrap a row of transparent `nm-button` items in `.nm-segmented`, add a single `.nm-segmented__indicator` element, and mark the active item with `aria-pressed="true"`. The CSS handles colours and the slide transition; **you position the indicator in JavaScript** by measuring the active button.

```html
<link rel="stylesheet" href="namirial-theme.css">

<div class="nm-segmented nm-segmented--md" role="group" aria-label="View">
  <span class="nm-segmented__indicator"></span>
  <button class="nm-button nm-button--secondary nm-button--md" aria-pressed="true">List</button>
  <button class="nm-button nm-button--secondary nm-button--md" aria-pressed="false">Board</button>
  <button class="nm-button nm-button--secondary nm-button--md" aria-pressed="false">Calendar</button>
</div>
```

```js
// Position the indicator under the active segment, then on every change.
function moveIndicator(root) {
  const active = root.querySelector('[aria-pressed="true"]');
  const bar = root.querySelector('.nm-segmented__indicator');
  if (!active || !bar) return;
  bar.style.left   = active.offsetLeft + 'px';
  bar.style.top    = active.offsetTop + 'px';
  bar.style.width  = active.offsetWidth + 'px';
  bar.style.height = active.offsetHeight + 'px';
}

document.querySelectorAll('.nm-segmented').forEach(root => {
  moveIndicator(root);
  root.addEventListener('click', e => {
    const btn = e.target.closest('.nm-button');
    if (!btn) return;
    root.querySelectorAll('.nm-button').forEach(b => b.setAttribute('aria-pressed', b === btn));
    moveIndicator(root);
  });
  window.addEventListener('resize', () => moveIndicator(root));
});
```

#### CSS classes

| Class | Applies to | Effect |
|-------|-----------|--------|
| `nm-segmented` | container | Track: background, border, padding, gap, positioning context |
| `nm-segmented--{size}` | container | Track radius & padding — `xs` · `sm` · `md` · `lg` · `xl` |
| `nm-segmented__indicator` | one child | The sliding pill; position it in JS |
| `nm-button nm-button--secondary nm-button--{size}` | each item | Transparent button; match the size to the track |
| `aria-pressed="true"` / `is-selected` | one item | Marks the active segment and flips its label colour |
