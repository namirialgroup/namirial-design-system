## Overview

A button invokes an action. Every button should communicate three things at a glance: that it is clickable, what it will do, and how important the action is relative to its neighbors. Use intent to set the action's weight, size to match its container, and style (solid vs. ghost) to control how loudly it sits on the page.

### When to use

- To commit a change or submit a form (`Save`, `Create`, `Sign document`)
- To advance a user through a flow (`Continue`, `Next step`)
- To trigger an immediate, self-contained action (`Send`, `Download`, `Copy link`)

### When not to use

- For navigation between pages — use a **link** instead. Buttons do things; links go places.
- To toggle a setting on or off — use a **switch** or **checkbox**.
- For a choice between a small set of options — use a **segmented control**.

## Anatomy

A button is a single focusable element: a label framed by geometry, with optional icons flanking the label. Color properties (fill, border, label) are driven by `--nm-button-*` custom properties. Geometry (height, padding, gap, radius) is baked directly into the size modifier classes (`nm-button--xs` through `nm-button--xl`).

## Solid & ghost

Every intent is available as **solid** (filled container with border) or **ghost** (transparent until hovered). Choose by hierarchy, not by taste.

### Solid

Filled buttons command attention. Use them for the action a user is expected to take — one primary on any given view, with secondaries alongside.

<div className="example">
  <button className="nm-button nm-button--primary nm-button--md">Save</button>
  <button className="nm-button nm-button--secondary nm-button--md">Cancel</button>
  <button className="nm-button nm-button--accent nm-button--md">Continue<Ic n="arrow-right" /></button>
  <button className="nm-button nm-button--negative nm-button--md">Delete</button>
</div>

### Ghost

Ghost buttons sit lighter on the canvas. Use them for tertiary actions, table-row actions, toolbar commands, and anywhere the filled chip would be visual noise.

<div className="example">
  <button className="nm-button nm-button--primary nm-button--md nm-button--ghost"><Ic n="share-2" />Share</button>

#### Choosing a size

- `xs` — inline chips, table-cell actions, filter bars
- `sm` — dense toolbars, compact dialogs
- `md` — default for forms, cards, panel footers
- `lg` — marketing hero, onboarding CTAs, empty states
- `xl` — signing surfaces, fullscreen confirmations, touch-first kiosks

## Icon variants

A button can appear as label-only, label + leading icon, label + trailing icon, or icon-only. Icons clarify intent — they never replace clear language.

<div className="example">
  <button className="nm-button nm-button--primary nm-button--md">Label only</button>
  <button className="nm-button nm-button--primary nm-button--md"><Ic n="download" />Leading icon</button>
  <button className="nm-button nm-button--primary nm-button--md">Trailing icon<Ic n="arrow-right" /></button>
  <button className="nm-button nm-button--primary nm-button--icon-only nm-button--md" aria-label="Settings"><Ic n="settings" /></button>
</div>

<p className="caption">Solid primary · md · four configurations</p>

#### Leading icon

Use when the icon adds concrete meaning to the label (`↓ Download`, `+ Add user`, `↻ Refresh`). The icon sits to the left of the label.

#### Trailing icon

Use when the icon indicates direction or state — `Continue →`, `Open menu ▾`, `External ↗`. Don't use trailing icons to decorate an already-clear verb.

#### Icon-only

Reserve for actions that are universally recognized (✕ close, ⋯ more, ◀ back) or that sit inside a dense bar where a label would break the layout. Icon-only buttons **must** have an `aria-label`.

## States

Every button responds to four interaction states. Hover and active colors come pre-baked from the tokens — you never hand-pick them.

<div className="example">
  <button className="nm-button nm-button--primary nm-button--md">Default</button>
  <button className="nm-button nm-button--primary nm-button--md" data-state="hover">Hover</button>
  <button className="nm-button nm-button--primary nm-button--md" data-state="active">Active</button>
  <button className="nm-button nm-button--primary nm-button--md" data-state="focus">Focus</button>
</div>

<p className="caption">Primary · md · four states</p>

#### Focus

Focus is rendered by a 2px `--theme-focus` outline, 2px offset from the button, that respects `:focus-visible`. Never suppress the focus ring. In dark theme the focus color shifts to a lighter blue for contrast — handled automatically by the theme layer.

#### No disabled state

Namirial buttons never ship a disabled appearance. A button that can be clicked but can't act is a dead end — users don't know what's wrong or how to fix it. Instead, keep the button enabled and let it trigger an inline error, field-level validation, or a toast that explains what needs to change.

## Accessibility

Namirial buttons inherit from the native `<button>` element. The tokens handle contrast; you handle semantics and labeling.

#### Semantics

- Use `<button type="button">` by default. Use `type="submit"` only inside a `<form>` that should submit on Enter.
- Never style an `<a>` as a button (or vice versa). A button does; a link navigates.

#### Keyboard

- Tab moves focus; Shift + Tab moves backwards.
- Space and Enter both trigger the button.
- Focus ring uses `:focus-visible`, so it appears on keyboard focus but not on mouse click — no override needed.

#### Contrast

- All seven intents, in both themes, meet WCAG 2.2 **AA** contrast for label-over-container at every state.
- Focus ring contrast is ≥ 3:1 against both the button and the surrounding background.

#### Labeling

- Icon-only buttons require `aria-label`. Make the label describe the action, not the icon ("Close dialog", not "X icon").
- Toggle buttons (e.g. Bold in a toolbar) require `aria-pressed`.
- Buttons that open a menu require `aria-haspopup` and `aria-expanded`.

## Token reference

Every button variant resolves to a handful of custom properties. When you need a one-off tweak, override these on a wrapper — never on the `.nm-button` rule itself.

#### Per-intent color tokens

| Token | Role |
|-------|------|
| `--nm-button-{intent}-default-bg` | Container fill at rest |
| `--nm-button-{intent}-hover-bg` | Fill on hover |
| `--nm-button-{intent}-active-bg` | Fill while pressed |
| `--nm-button-{intent}-default-border` | Border at rest |
| `--nm-button-{intent}-fg` | Label + icon color (solid) |
| `--nm-button-ghost-{intent}-fg` | Label color, ghost style |

<p className="caption"><code>{'{intent}'}</code> = primary · secondary · accent · positive · negative · warning · info</p>

#### Per-size geometry values

| Property | Role | xs | sm | md | lg | xl |
|----------|------|----|----|----|----|----|
| `height` | Button height | 24px | 32px | 40px | 48px | 56px |
| `font-size` | Label size | 12px | 14px | 16px | 20px | 24px |
| `padding-inline` | Horizontal padding | 8px | 12px | 16px | 24px | 24px |
| `gap` | Icon/label gap | 8px | 8px | 12px | 12px | 16px |
| `border-radius` | Corner radius | 6px | 8px | 10px | 12px | 12px |

<p className="caption">Values are baked into <code>.nm-button--{'{'+'size}'}</code> modifier classes. No custom properties to override — use a different size class instead.</p>

  <i class="icon-arrow-right"></i>
